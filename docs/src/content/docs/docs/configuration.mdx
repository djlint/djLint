Configuration goes in your project's `pyproject.toml`, a `djlint.toml` or `.djlint.toml`, or a `.djlintrc`. Command line options override the config file, but a flag can only turn an option on, so it can't turn off a switch the config file sets. The project's settings override a global config file given with `--configuration`, unless `--prefer-configuration` is set.

djLint looks for these files upward from the first path it checks (for `-`, from the folder of `--stdin-filename`, or from the current directory without it). It stops at the first folder that holds a `djlint.toml`, a `.djlint.toml`, a `.djlintrc`, a `.djlint_rules.yaml` or a `pyproject.toml` with `[tool.djlint]`, and never goes past the root of a repository (a folder with a `.git` folder or file, or a `.hg` folder). A `pyproject.toml` without djLint settings doesn't stop it, so a package in a monorepo with its own `pyproject.toml` gets the settings of the repository. djLint reads only the folder it stops at: `[tool.djlint]` in its `pyproject.toml` if that table sets anything, otherwise its `djlint.toml` or `.djlint.toml`, otherwise its `.djlintrc`, and warns about the ones there that it doesn't read.

Where neither the command line nor the configuration sets `indent` or `max_line_length`, djLint takes `indent_size` or `max_line_length` from `.editorconfig` files, as editors do: each file gets them by its own path, the nearest `.editorconfig` wins and the ones above it fill in, up to one with `root = true` or the project root.

The format for `pyproject.toml` is `toml`.

```toml
[tool.djlint]
profile = "django"
ignore = ["H014", "H015"]
```

The format for `djlint.toml` and `.djlint.toml` is `toml`.

```toml
profile = "django"
ignore = ["H014", "H015"]
```

The format for `.djlintrc` is `json`.

```json
{ "profile": "django", "ignore": ["H014", "H015"] }
```

Options that take several values, such as `ignore`, take a list. A comma-separated string such as `"H014,H015"` works too, and is what djLint before 1.41 needs.

From version 1.51, djLint warns about a setting or a rule code it doesn't know, and names the closest one it does.
