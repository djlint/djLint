## 安装

djLint 基于 [Python](https://python.org) 开发，发布在 [PyPI](https://pypi.org/project/djlint/) 上。使用 [uv](https://docs.astral.sh/uv/) 将其添加为项目的开发依赖：

```bash
uv add --dev djlint
```

或者将其作为独立工具安装：

```bash
uv tool install djlint
```

或者使用 pip 安装：

```bash
pip install djlint
```

或者使用 [pipx](https://pipx.pypa.io/) 安装：

```bash
pipx install djlint
```

或者在 macOS 或 Linux 上使用社区维护的 [Homebrew formula](https://formulae.brew.sh/formula/djlint) 安装：

```bash
brew install djlint
```

_或者使用 npm 安装 - **注意**：npm 包只是一个包装器，其安装脚本会用系统路径中的 `python3` 执行 `pip install --upgrade djlint`。npm 无法管理或卸载实际安装的包 - 建议尽量直接使用 pip。_

```bash
npm i djlint
```

如需在每次提交时运行 djLint，请参阅 [pre-commit](/zh/docs/integrations/#pre-commit)。

## 使用路径或标准输入（stdin）

djLint 可以通过路径或标准输入（stdin）运行。

通过路径运行 -

```bash
djlint /path/to/templates --lint
```

或者针对指定文件 -

```bash
djlint /path/to/this.mustache --lint
```

或者使用标准输入（stdin） -

```bash
echo "<div></div>" | djlint -
```

标准输入（stdin）也可用于重新格式化代码。输出将仅包含格式化后的代码，而不包含任何消息。

```bash
echo "<div></div>" | djlint - --reformat
```

输出结果 -

```html
<div></div>
```

从标准输入（stdin）读取时，djLint 没有真实路径可用来匹配 `per-file-ignores` 或显示在消息中，因此默认使用 `-`。可以通过 `--stdin-filename` 告诉 djLint 传入内容的真实路径，例如编辑器集成在保存时通过管道传入文件内容的情况。

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## 退出码

| 退出码 | 含义                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| `0`    | 要求 djLint 检查的内容全部没有问题，或者找到的每个文件都被你的配置跳过。                                    |
| `1`    | djLint 发现了代码检查错误，或需要重新格式化的文件。使用 `--warn` 时，这些问题以警告形式报告，退出码为 `0`。 |
| `2`    | djLint 没有检查你要求的内容：路径没有匹配到任何文件、命令行或配置无效，或者 djLint 运行失败。               |

只有退出码 `1` 表示 djLint 检查了你的模板并发现了问题。退出码 `2` 总是表示这次运行本身没有完成，因此流水线可以区别对待这两种情况，而不必猜测。

退出码 `2` 能发现什么都没检查的运行：路径写错、`--extension` 不再匹配，或者模板被移动了位置。没有它，这样的运行会悄无声息地通过，而实际上一个模板都没有检查。

djLint *确实*找到、但通过 `exclude`、`extend_exclude`、`use_gitignore` 或 `require_pragma` 有意跳过的文件不算错误。这种运行以 `0` 退出，因为配置完全按要求生效了。这也让 `exclude` 能在 pre-commit 下正常工作：无论你是否希望 djLint 检查，pre-commit 都会传入所有已暂存文件的名称。

如果在你的流水线中，路径下没有模板属于正常情况，可以通过 `allow_empty_input` 关闭退出码 `2`：

```bash
djlint /path/to/templates --lint --allow-empty-input
```
