## Kurulum

djLint, [Python](https://python.org) 3.11 veya daha yenisini gerektirdiği [PyPI](https://pypi.org/project/djlint/) üzerinde ve kendi Python'ıyla gelen [npm](https://www.npmjs.com/package/djlint) üzerinde yayımlanır. Bir Python projesine uv ya da pip ile, Angular uygulaması, Eleventy sitesi veya Shopify teması gibi bir JavaScript projesine npm ile ekleyin.

<Tabs>
<TabItem label="uv">

[uv](https://docs.astral.sh/uv/) ile projenize geliştirme bağımlılığı olarak ekleyin:

```bash
uv add --dev djlint
```

Ya da bağımsız bir araç olarak kurun:

```bash
uv tool install djlint
```

</TabItem>
<TabItem label="pip">

```bash
pip install djlint
```

</TabItem>
<TabItem label="npm">

npm paketi kendi Python'ıyla gelir, bu yüzden yalnızca Node.js 16.9 veya daha yenisine ihtiyaç duyar. x64, Arm64, ppc64le, s390x ve riscv64 üzerinde Linux, x64 ve Arm64 üzerinde macOS ve x64, x86 ve Arm64 üzerinde Windows için derlemeleri vardır. Alpine gibi musl kullanan Linux'ta x64 ve Arm64 üzerinde çalışır. Projenize geliştirme bağımlılığı olarak ekleyin:

```bash
npm i -D djlint
```

Ya da genel olarak kurun:

```bash
npm i -g djlint
```

</TabItem>
<TabItem label="pipx">

[pipx](https://pipx.pypa.io/) ile:

```bash
pipx install djlint
```

</TabItem>
<TabItem label="Homebrew">

macOS veya Linux'ta topluluk tarafından sürdürülen [Homebrew formülüyle](https://formulae.brew.sh/formula/djlint):

```bash
brew install djlint
```

</TabItem>
</Tabs>

djLint'i düzenleyicinizde ya da her commit'te çalıştırmak için [Entegrasyonlar](/tr/docs/integrations/) sayfasına ve [pre-commit](/tr/docs/integrations/#pre-commit) bölümüne bakın.

:::note[Not]
`djlint` komutu bulunamıyorsa kurulduğu klasörü PATH'inize ekleyin. djLint bir Python ortamına kuruluysa, o ortamın Python'u ile çalıştırılan `python -m djlint` de onu çalıştırır.
:::

## İlk çalıştırma

djLint'e şablonlarınızın bulunduğu klasörü verin ve `--profile` ile şablon dilinizi belirtin. Hangi linter kurallarının çalışacağını ve şablon söz diziminin nasıl biçimlendirileceğini profil belirler. Bir Django projesi için:

Şablonları denetleyin (denetleme varsayılan mod olduğundan `--lint` yazmasanız da olur):

```bash
djlint templates --lint --profile=django
```

Biçimlendirmenin neyi değiştireceğine bakın. `--check` ile djLint bir diff yazdırır ve dosyalara dokunmaz:

```bash
djlint templates --check --profile=django
```

Dosyaları yerinde biçimlendirin:

```bash
djlint templates --reformat --profile=django
```

Tüm profiller [`profile`](/tr/docs/configuration/#profile) seçeneğinde listelenir. Her şablon dilinin ayrıca kendi sayfası vardır, örneğin [Django](/tr/docs/languages/django/), [Jinja](/tr/docs/languages/jinja/) ya da [Handlebars](/tr/docs/languages/handlebars/). Profili her seferinde yazmamak için bir yapılandırma dosyasında nasıl ayarlayacağınız da orada gösterilir.

djLint'i projeye `uv add --dev` ile eklediyseniz projenin ortamındadır: komutların başına `uv run` ekleyin, örneğin `uv run djlint templates --lint --profile=django`. `npm i -D` ile eklediyseniz başlarına bunun yerine `npx` ekleyin, örneğin `npx djlint templates --lint --profile=django`.

## Yol ya da stdin kullanımı

djLint bir yolla ya da stdin ile çalışır.

Bir yolla çalıştırma:

```bash
djlint /path/to/templates --lint
```

Ya da belirli bir dosyayla:

```bash
djlint /path/to/this.mustache --lint
```

Ya da stdin ile:

```bash
echo "<div></div>" | djlint -
```

Stdin kodu yeniden biçimlendirmek için de kullanılabilir. Çıktı, mesajlar olmadan yalnızca biçimlendirilmiş koddan oluşur.

```bash
echo "<div></div>" | djlint - --reformat
```

Çıktı:

```html
<div></div>
```

stdin'den okurken djLint'in `per-file-ignores` ile eşleştireceği ya da mesajlarda göstereceği gerçek bir yol yoktur; bu yüzden varsayılan olarak `-` kullanır. Aktarılan içeriğin gerçek yolunu djLint'e bildirmek için `--stdin-filename` verin; örneğin bir düzenleyici entegrasyonu kaydetme sırasında bir dosyanın içeriğini aktardığında.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Çıkış kodları

| Kod | Anlamı                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | djLint'ten denetlemesi istenen her şey temiz ya da bulduğu her dosya yapılandırmanız tarafından atlandı.                                                                                        |
| `1` | djLint lint hataları ya da yeniden biçimlendirilmesi gereken dosyalar buldu. `--warn` bunları uyarı olarak bildirir ve bunun yerine `0` ile çıkar.                                              |
| `2` | djLint istediğiniz şeyi denetlemedi: yollar hiçbir dosyayla eşleşmedi, bir dosya okunamadı (UTF-8 değil ya da izin yok), komut satırı ya da yapılandırma geçersizdi veya djLint başarısız oldu. |

Yalnızca `1` kodu, djLint'in şablonlarınıza baktığı ve bulduklarını beğenmediği anlamına gelir. Böylece bir işlem hattı başarısız bir denetimi, hiçbir şeyi denetlemeyen bir çalıştırmadan ayırabilir; örneğin yanlış bir yol verilmiş ya da `--extension` artık eşleşmiyordur.

djLint'in bulduğu ve ardından `exclude`, `extend_exclude`, `use_gitignore` ya da `require_pragma` aracılığıyla bilerek atladığı dosyalar hata sayılmaz; `exclude` seçeneğinin pre-commit altında çalışmasını sağlayan da budur. İşlem hattınızda hiç şablon içermeyen bir yol olağansa `2` kodunu [`allow_empty_input`](/tr/docs/configuration/#allow-empty-input) ile kapatın:

```bash
djlint /path/to/templates --lint --allow-empty-input
```
