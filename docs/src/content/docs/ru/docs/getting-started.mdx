## Установка

Для djLint нужен [Python](https://python.org) 3.11 или новее. Он опубликован в [PyPI](https://pypi.org/project/djlint/).

<Tabs>
<TabItem label="uv">

С [uv](https://docs.astral.sh/uv/) добавьте его в проект как зависимость для разработки:

```bash
uv add --dev djlint
```

Или установите его как отдельный инструмент:

```bash
uv tool install djlint
```

</TabItem>
<TabItem label="pip">

```bash
pip install djlint
```

</TabItem>
<TabItem label="npm">

npm-пакет поставляется со своим Python, так что ему нужен только Node.js 16.9 или новее. Есть сборки для Linux на x64, Arm64, ppc64le, s390x и riscv64, macOS на x64 и Arm64 и Windows на x64, x86 и Arm64. На Linux с musl, например Alpine, он работает на x64 и Arm64. Добавьте его в проект как зависимость для разработки:

```bash
npm i -D djlint
```

Или установите его глобально:

```bash
npm i -g djlint
```

</TabItem>
<TabItem label="pipx">

Через [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

</TabItem>
<TabItem label="Homebrew">

Через [формулу Homebrew](https://formulae.brew.sh/formula/djlint), которую поддерживает сообщество, на macOS или Linux:

```bash
brew install djlint
```

</TabItem>
</Tabs>

Чтобы запускать djLint в редакторе или при каждом коммите, см. разделы [Интеграции](/ru/docs/integrations/) и [pre-commit](/ru/docs/integrations/#pre-commit).

:::note[Примечание]
Если команда `djlint` не найдена, добавьте в PATH папку, куда он установлен. Если djLint установлен в окружение Python, его запустит и `python -m djlint` с Python из этого окружения.
:::

## Первый запуск

Передайте djLint папку с шаблонами и укажите в `--profile` язык шаблонов. От профиля зависит, какие правила линтера сработают и как будет отформатирован синтаксис шаблонов. Для проекта на Django:

Проверьте шаблоны (это режим по умолчанию, так что `--lint` можно не писать):

```bash
djlint templates --lint --profile=django
```

Посмотрите, что изменит форматирование. С `--check` djLint выводит diff и не трогает файлы:

```bash
djlint templates --check --profile=django
```

Отформатируйте файлы на месте:

```bash
djlint templates --reformat --profile=django
```

Все профили перечислены в описании опции [`profile`](/ru/docs/configuration/#profile). У каждого языка шаблонов есть и своя страница, например [Django](/ru/docs/languages/django/), [Jinja](/ru/docs/languages/jinja/) или [Handlebars](/ru/docs/languages/handlebars/). Там же показано, как задать профиль в файле конфигурации, чтобы не передавать его каждый раз.

Если djLint добавлен в проект через `uv add --dev`, он лежит в окружении проекта: запускайте команды через `uv run`, например `uv run djlint templates --lint --profile=django`. После `npm i -D` запускайте их через `npx`, например `npx djlint templates --lint --profile=django`.

## Путь или stdin

djLint принимает на вход путь или стандартный ввод (stdin).

Запуск с путём:

```bash
djlint /path/to/templates --lint
```

Или с конкретным файлом:

```bash
djlint /path/to/this.mustache --lint
```

Или через stdin:

```bash
echo "<div></div>" | djlint -
```

Через stdin можно и переформатировать код. Тогда выводится только отформатированный код, без сообщений.

```bash
echo "<div></div>" | djlint - --reformat
```

Вывод:

```html
<div></div>
```

При чтении из stdin у djLint нет настоящего пути, с которым можно сопоставить `per-file-ignores` и который можно показать в сообщениях, поэтому по умолчанию используется `-`. Передайте `--stdin-filename`, чтобы сообщить djLint настоящий путь переданного содержимого, например когда интеграция с редактором передаёт содержимое файла при сохранении.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Коды завершения

| Код | Значение                                                                                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | Всё, что djLint должен был проверить, в порядке, или каждый найденный файл пропущен согласно вашей конфигурации.                                                                                         |
| `1` | djLint нашёл ошибки линтера или файлы, которые нужно переформатировать. С `--warn` они выводятся как предупреждения, а код завершения вместо этого будет `0`.                                            |
| `2` | djLint не проверил то, что вы просили: пути не совпали ни с одним файлом, файл не удалось прочитать (не UTF-8 или нет прав), командная строка или конфигурация некорректны либо в djLint произошёл сбой. |

Только код `1` означает, что djLint просмотрел ваши шаблоны и ему не понравилось то, что он нашёл, поэтому конвейер может отличить непройденную проверку от запуска, который ничего не проверил, например с неверным путём или с `--extension`, который больше ничему не соответствует.

Файлы, которые djLint нашёл, а затем намеренно пропустил из-за `exclude`, `extend_exclude`, `use_gitignore` или `require_pragma`, ошибкой не считаются, и благодаря этому `exclude` работает в pre-commit. Если для вашего конвейера нормально, что по пути нет шаблонов, отключите код `2` параметром [`allow_empty_input`](/ru/docs/configuration/#allow-empty-input):

```bash
djlint /path/to/templates --lint --allow-empty-input
```
