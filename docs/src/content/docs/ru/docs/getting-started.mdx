## Установка

djLint написан на [Python](https://python.org) и опубликован в [PyPI](https://pypi.org/project/djlint/). С [uv](https://docs.astral.sh/uv/) добавьте его в проект как зависимость для разработки:

```bash
uv add --dev djlint
```

Или установите его как отдельный инструмент:

```bash
uv tool install djlint
```

Или через pip:

```bash
pip install djlint
```

Или через [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

Или через [формулу Homebrew](https://formulae.brew.sh/formula/djlint), которую поддерживает сообщество, на macOS или Linux:

```bash
brew install djlint
```

_Или через npm. **Внимание**: npm-пакет — лишь обёртка. Его установочный скрипт запускает pip для того `python3`, который окажется в системном PATH, и устанавливает версию djLint, соответствующую этому релизу npm-пакета, из-за чего более новый djLint может быть заменён более старым. npm не управляет самим пакетом и не удаляет его, поэтому по возможности используйте pip._

```bash
npm i djlint
```

Чтобы запускать djLint при каждом коммите, см. раздел [pre-commit](/ru/docs/integrations/#pre-commit).

## Путь или stdin

djLint принимает на вход путь или стандартный ввод (stdin).

Запуск с путём:

```bash
djlint /path/to/templates --lint
```

Или с конкретным файлом:

```bash
djlint /path/to/this.mustache --lint
```

Или через stdin:

```bash
echo "<div></div>" | djlint -
```

Через stdin можно и переформатировать код. Тогда выводится только отформатированный код, без сообщений.

```bash
echo "<div></div>" | djlint - --reformat
```

Вывод:

```html
<div></div>
```

При чтении из stdin у djLint нет настоящего пути, с которым можно сопоставить `per-file-ignores` и который можно показать в сообщениях, поэтому по умолчанию используется `-`. Передайте `--stdin-filename`, чтобы сообщить djLint настоящий путь переданного содержимого, например когда интеграция с редактором передаёт содержимое файла при сохранении.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Коды завершения

| Код | Значение                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | Всё, что djLint должен был проверить, в порядке, или каждый найденный файл пропущен согласно вашей конфигурации.                                          |
| `1` | djLint нашёл ошибки линтера или файлы, которые нужно переформатировать. С `--warn` они выводятся как предупреждения, а код завершения вместо этого — `0`. |
| `2` | djLint не проверил то, что вы просили: пути не совпали ни с одним файлом, командная строка или конфигурация некорректны либо в djLint произошёл сбой.     |

Только код `1` означает, что djLint просмотрел ваши шаблоны и ему не понравилось то, что он нашёл. Код `2` всегда означает, что сам запуск не справился с задачей, поэтому конвейер может обрабатывать эти два случая по-разному.

Именно код `2` выявляет запуск, который вообще ничего не проверил: неверный путь, `--extension`, который больше ничему не соответствует, или перемещённые шаблоны. Без него такой запуск молча проходит успешно.

Файлы, которые djLint _нашёл_, а затем намеренно пропустил из-за `exclude`, `extend_exclude`, `use_gitignore` или `require_pragma`, ошибкой не считаются. Такой запуск завершается с кодом `0`, потому что конфигурация сделала ровно то, что ей было велено. Благодаря этому `exclude` и работает в pre-commit, который передаёт имена файлов из индекса независимо от того, хотите ли вы, чтобы djLint их проверял.

Если для вашего конвейера нормально, что по пути действительно нет шаблонов, отключите код `2` параметром `allow_empty_input`:

```bash
djlint /path/to/templates --lint --allow-empty-input
```
