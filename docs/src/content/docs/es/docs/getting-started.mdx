## Instalación

djLint está escrito en [Python](https://python.org) y publicado en [PyPI](https://pypi.org/project/djlint/). Con [uv](https://docs.astral.sh/uv/), añádelo a tu proyecto como dependencia de desarrollo:

```bash
uv add --dev djlint
```

O instálalo como herramienta independiente:

```bash
uv tool install djlint
```

O con pip:

```bash
pip install djlint
```

O con [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

O con la [fórmula de Homebrew](https://formulae.brew.sh/formula/djlint) que mantiene la comunidad, en macOS o Linux:

```bash
brew install djlint
```

_O con npm. **Advertencia**: el paquete de npm es solo un envoltorio. Su script de instalación ejecuta `pip install --upgrade djlint` con el `python3` que haya en la ruta de tu sistema, y npm no gestionará ni desinstalará el paquete real, así que, si puedes, usa pip._

```bash
npm i djlint
```

Para ejecutar djLint en cada commit, consulta [pre-commit](/es/docs/integrations/#pre-commit).

## Uso de la línea de comandos

djLint es una aplicación de línea de comandos. Consulta la página de [configuración](/es/docs/configuration/) para una configuración avanzada.

## Ruta o stdin

djLint funciona con una ruta o con stdin.

Con una ruta:

```bash
djlint /path/to/templates --lint
```

O con un archivo concreto:

```bash
djlint /path/to/this.mustache --lint
```

O con stdin:

```bash
echo "<div></div>" | djlint -
```

stdin también sirve para reformatear código. La salida será solo el código formateado, sin mensajes.

```bash
echo "<div></div>" | djlint - --reformat
```

Salida:

```html
<div></div>
```

Al leer de stdin, djLint no tiene una ruta real con la que comparar `per-file-ignores` ni que mostrar en los mensajes, así que usa `-` por defecto. Pasa `--stdin-filename` para indicarle a djLint la ruta real del contenido que recibe por la tubería, por ejemplo cuando una integración con un editor le pasa el contenido de un archivo al guardarlo.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Códigos de salida

| Código | Significado                                                                                                                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | Todo lo que se le pidió revisar a djLint está limpio, o tu configuración omitió todos los archivos que encontró.                                           |
| `1`    | djLint encontró errores del linter, o archivos que hay que reformatear. `--warn` los muestra como advertencias y sale con `0` en su lugar.                 |
| `2`    | djLint no revisó lo que le pediste: las rutas no coincidieron con ningún archivo, la línea de comandos o la configuración no eran válidas, o djLint falló. |

Solo el código `1` significa que djLint examinó tus plantillas y no le gustó lo que encontró. El código `2` siempre significa que la propia ejecución no cumplió su cometido, así que un pipeline puede tratar ambos casos de forma distinta.

El código `2` es el que detecta una ejecución que no revisó nada en absoluto: una ruta incorrecta, una `--extension` que ya no coincide o plantillas que se han movido. Sin él, una ejecución así pasa sin avisar.

Los archivos que djLint _sí_ encontró y luego omitió a propósito, mediante `exclude`, `extend_exclude`, `use_gitignore` o `require_pragma`, no son un error. Esa ejecución sale con `0`, porque la configuración hizo exactamente lo que se le indicó. Es también lo que permite que `exclude` funcione con pre-commit, que pasa los nombres de tus archivos preparados para el commit tanto si quieres que djLint los examine como si no.

Si en tu pipeline es normal que una ruta no tenga plantillas, desactiva el código `2` con `allow_empty_input`:

```bash
djlint /path/to/templates --lint --allow-empty-input
```
