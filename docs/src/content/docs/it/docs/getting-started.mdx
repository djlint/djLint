## Installazione

djLint è scritto in [Python](https://python.org) ed è pubblicato su [PyPI](https://pypi.org/project/djlint/). Con [uv](https://docs.astral.sh/uv/), aggiungilo al progetto come dipendenza di sviluppo:

```bash
uv add --dev djlint
```

Oppure installalo come strumento autonomo:

```bash
uv tool install djlint
```

Oppure con pip:

```bash
pip install djlint
```

Oppure con [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

Oppure con la [formula Homebrew](https://formulae.brew.sh/formula/djlint) mantenuta dalla community, su macOS o Linux:

```bash
brew install djlint
```

_Oppure con npm. **Attenzione**: il pacchetto npm è solo un wrapper. Il suo script di installazione esegue `pip install --upgrade djlint` con il `python3` che si trova nel PATH di sistema, e npm non gestisce né disinstalla il pacchetto vero e proprio, quindi, se puoi, preferisci pip._

```bash
npm i djlint
```

Per eseguire djLint a ogni commit, consulta [pre-commit](/it/docs/integrations/#pre-commit).

## Percorso o stdin

djLint funziona con un percorso o con stdin.

Esecuzione con un percorso:

```bash
djlint /path/to/templates --lint
```

Oppure con un file specifico:

```bash
djlint /path/to/this.mustache --lint
```

Oppure con stdin:

```bash
echo "<div></div>" | djlint -
```

Stdin si può usare anche per riformattare il codice. L'output conterrà solo il codice formattato, senza messaggi.

```bash
echo "<div></div>" | djlint - --reformat
```

Output:

```html
<div></div>
```

Quando legge da stdin, djLint non ha un percorso reale da confrontare con `per-file-ignores` o da mostrare nei messaggi, quindi usa `-` per impostazione predefinita. Passa `--stdin-filename` per indicare a djLint il percorso reale del contenuto ricevuto tramite pipe, ad esempio quando un'integrazione con l'editor gli passa il contenuto di un file al salvataggio.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Codici di uscita

| Codice | Significato                                                                                                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `0`    | Tutto ciò che djLint doveva controllare è pulito, oppure ogni file trovato è stato escluso dalla configurazione.                                                                                       |
| `1`    | djLint ha trovato errori di lint o file da riformattare. Con `--warn` vengono segnalati come avvisi e il codice di uscita è invece `0`.                                                                |
| `2`    | djLint non ha controllato ciò che gli hai chiesto: i percorsi non corrispondevano a nessun file, la riga di comando o la configurazione non erano valide, oppure djLint si è interrotto con un errore. |

Solo il codice `1` significa che djLint ha esaminato i tuoi template e ciò che ha trovato non gli è piaciuto. Il codice `2` significa sempre che l'esecuzione stessa non ha fatto il suo lavoro, così una pipeline può trattare i due casi in modo diverso.

Il codice `2` intercetta un'esecuzione che non ha controllato proprio nulla: un percorso sbagliato, un `--extension` che non corrisponde più, oppure template che sono stati spostati. Senza di esso un'esecuzione del genere passa in silenzio.

I file che djLint _ha_ trovato e poi escluso di proposito, tramite `exclude`, `extend_exclude`, `use_gitignore` o `require_pragma`, non sono un errore. In quel caso il codice di uscita è `0`, perché la configurazione ha fatto esattamente ciò che le era stato chiesto. Così `exclude` funziona anche con pre-commit, che passa i nomi dei file in stage indipendentemente dal fatto che tu voglia o meno che djLint li esamini.

Se per la tua pipeline è normale un percorso che legittimamente non contiene template, disattiva il codice `2` con `allow_empty_input`:

```bash
djlint /path/to/templates --lint --allow-empty-input
```
