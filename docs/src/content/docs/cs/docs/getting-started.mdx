## Instalace

djLint potřebuje [Python](https://python.org) 3.11 nebo novější a je publikovaný na [PyPI](https://pypi.org/project/djlint/).

<Tabs>
<TabItem label="uv">

S [uv](https://docs.astral.sh/uv/) ho přidejte do projektu jako vývojovou závislost:

```bash
uv add --dev djlint
```

Nebo ho nainstalujte jako samostatný nástroj:

```bash
uv tool install djlint
```

</TabItem>
<TabItem label="pip">

```bash
pip install djlint
```

</TabItem>
<TabItem label="pipx">

Pomocí [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

</TabItem>
<TabItem label="Homebrew">

V systémech macOS a Linux pomocí [formule Homebrew](https://formulae.brew.sh/formula/djlint), kterou spravuje komunita:

```bash
brew install djlint
```

</TabItem>
<TabItem label="npm">

Balíček npm si nese vlastní Python, takže potřebuje jen Node.js 16.9 nebo novější. Má sestavení pro Linux na x64, Arm64, ppc64le, s390x a riscv64, macOS na x64 a Arm64 a Windows na x64, x86 a Arm64. Na Linuxu s musl, například Alpine, běží na x64 a Arm64. Přidejte ho do projektu jako vývojovou závislost:

```bash
npm i -D djlint
```

Pak ho spouštějte přes `npx djlint`, například `npx djlint . --lint`.

</TabItem>
</Tabs>

Chcete-li djLint spouštět v editoru nebo při každém commitu, přečtěte si [Integrace](/cs/docs/integrations/) a [pre-commit](/cs/docs/integrations/#pre-commit).

:::note[Poznámka]
Pokud příkaz `djlint` není nalezen, přidejte složku, do které se nainstaloval, do své PATH. Je-li djLint nainstalovaný v prostředí Pythonu, spustí ho i `python -m djlint` s Pythonem tohoto prostředí.
:::

## První spuštění

Předejte djLint složku se šablonami a v `--profile` uveďte svůj šablonovací jazyk. Na profilu závisí, která pravidla linteru se spustí a jak se naformátuje syntaxe šablon. Pro projekt v Djangu:

Lintujte šablony (lintování je výchozí režim, takže `--lint` můžete vynechat):

```bash
djlint templates --lint --profile=django
```

Podívejte se, co by formátování změnilo. S `--check` djLint vypíše diff a soubory nechá beze změny:

```bash
djlint templates --check --profile=django
```

Naformátujte soubory přímo na místě:

```bash
djlint templates --reformat --profile=django
```

Všechny profily uvádí volba [`profile`](/cs/docs/configuration/#profile). Každý šablonovací jazyk má navíc vlastní stránku, například [Django](/cs/docs/languages/django/), [Jinja](/cs/docs/languages/jinja/) nebo [Handlebars](/cs/docs/languages/handlebars/), kde se dočtete, jak profil nastavit v konfiguračním souboru, abyste ho nemuseli zadávat pokaždé.

Pokud jste djLint přidali do projektu přes `uv add --dev`, je v prostředí projektu: příkazy spouštějte s `uv run` na začátku, například `uv run djlint templates --lint --profile=django`.

## Cesta, nebo stdin

djLint pracuje s cestou i se standardním vstupem (stdin).

Spuštění s cestou:

```bash
djlint /path/to/templates --lint
```

Nebo s konkrétním souborem:

```bash
djlint /path/to/this.mustache --lint
```

Nebo se stdin:

```bash
echo "<div></div>" | djlint -
```

Stdin lze použít i k přeformátování kódu. Výstupem bude jen naformátovaný kód bez dalších zpráv.

```bash
echo "<div></div>" | djlint - --reformat
```

Výstup:

```html
<div></div>
```

Při čtení ze stdin nemá djLint žádnou skutečnou cestu, se kterou by porovnal `per-file-ignores` nebo kterou by zobrazil ve zprávách, a proto ve výchozím nastavení používá `-`. Pomocí `--stdin-filename` sdělíte djLint skutečnou cestu obsahu předaného rourou, například když integrace v editoru při ukládání posílá obsah souboru rourou.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Návratové kódy

| Kód | Význam                                                                                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `0` | Vše, co měl djLint zkontrolovat, je v pořádku, nebo vaše konfigurace přeskočila všechny soubory, které našel.                                                                                                      |
| `1` | djLint našel chyby lintování nebo soubory, které je potřeba přeformátovat. `--warn` je místo toho nahlásí jako varování a skončí s kódem `0`.                                                                      |
| `2` | djLint nezkontroloval to, co jste chtěli: cestám neodpovídaly žádné soubory, některý soubor nešel přečíst (není v UTF-8 nebo chybí oprávnění), příkazový řádek nebo konfigurace byly neplatné, nebo djLint selhal. |

Jen kód `1` znamená, že se djLint na vaše šablony podíval a nelíbilo se mu, co našel, takže pipeline rozliší neúspěšnou kontrolu od spuštění, které nic nezkontrolovalo, například s chybnou cestou nebo s `--extension`, které už neodpovídá.

Soubory, které djLint našel a pak záměrně přeskočil kvůli `exclude`, `extend_exclude`, `use_gitignore` nebo `require_pragma`, nejsou chybou, a díky tomu funguje `exclude` v pre-commit. Pokud je pro vaši pipeline normální, že cesta neobsahuje žádné šablony, vypněte kód `2` pomocí [`allow_empty_input`](/cs/docs/configuration/#allow-empty-input):

```bash
djlint /path/to/templates --lint --allow-empty-input
```
