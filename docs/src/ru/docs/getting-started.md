# {{ "getting_started" | i18n }}

## Установка

djLint написан на [Python](https://python.org), его можно установить из [PyPI](https://pypi.org/project/djlint/) простым запуском:

```bash
pip install djlint
```

Или как отдельный инструмент с помощью [uv](https://docs.astral.sh/uv/):

```bash
uv tool install djlint
```

Или с помощью [pipx](https://pipx.pypa.io/):

```bash
pipx install djlint
```

Или с помощью формулы [Homebrew](https://formulae.brew.sh/formula/djlint), поддерживаемой сообществом, на macOS или Linux:

```bash
brew install djlint
```

_Или с помощью npm - **внимание**: npm-пакет - это лишь обёртка, его установочный скрипт запускает `pip install --upgrade djlint` для того `python3`, который находится в вашем системном пути. npm не управляет установленным пакетом и не удалит его - по возможности используйте pip напрямую._

```bash
npm i djlint
```

## Использование Path против Stdin

djLint работает с путем или stdin.

Запуск с путём -

```bash
djlint /path/to/templates --lint
```

Или конкретный файл -

```bash
djlint /path/to/this.mustache --lint
```

Или с помощью stdin -

```bash
echo "<div></div>" | djlint -
```

Stdin также может быть использован для переформатирования кода. На выходе будет только отформатированный код без сообщений.

```bash
echo "<div></div>" | djlint - --reformat
```

Вывод -

```html
<div></div>
```

При чтении из stdin у djLint нет настоящего пути, который можно сопоставить с `per-file-ignores` или показать в сообщениях, поэтому по умолчанию используется `-`. Передайте `--stdin-filename`, чтобы указать djLint настоящий путь переданного содержимого, например когда интеграция с редактором при сохранении передаёт содержимое файла через stdin.

```bash
echo "<div></div>" | djlint - --stdin-filename templates/index.html
```

## Коды выхода

| Код | Значение                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | Всё, что djLint попросили проверить, в порядке, или все найденные файлы пропущены по вашей конфигурации.                                                  |
| `1` | djLint нашёл ошибки линтинга или файлы, которые нужно переформатировать. С `--warn` они выводятся как предупреждения, а код выхода будет `0`.             |
| `2` | djLint не проверил то, что вы просили: пути не совпали ни с одним файлом, командная строка или конфигурация некорректны, или djLint завершился с ошибкой. |

Только код `1` означает, что djLint просмотрел ваши шаблоны и нашёл в них проблемы. Код `2` всегда означает, что сам запуск не удался, поэтому пайплайн может обрабатывать эти случаи по-разному и не гадать.

Код `2` ловит запуск, который вообще ничего не проверил: неверный путь, `--extension`, который больше не подходит, или переехавшие шаблоны. Без него такой запуск молча проходит, не просмотрев ни одного шаблона.

Файлы, которые djLint _нашёл_ и намеренно пропустил из-за `exclude`, `extend_exclude`, `use_gitignore` или `require_pragma`, ошибкой не считаются. Такой запуск завершается с кодом `0`, потому что конфигурация сделала ровно то, что ей было сказано. Благодаря этому `exclude` работает и в pre-commit, который передаёт имена всех файлов из индекса, хотите вы, чтобы djLint их проверял, или нет.

Если путь без шаблонов для вашего пайплайна нормален, отключите код `2` опцией `allow_empty_input`:

```bash
djlint /path/to/templates --lint --allow-empty-input
```
