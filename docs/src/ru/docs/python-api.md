# Python API

`djlint.api` форматирует и проверяет текст из программы на Python и даёт те же результаты, что и командная строка. Он предназначен для редакторов, инструментов сборки и всего остального, что держит шаблон в памяти. Всё остальное в пакете может измениться в любом релизе, поэтому используйте этот модуль, а не `djlint.settings` или `djlint.lint`.

```python
from djlint.api import format_text, lint_text, load_config

config = load_config("templates", profile="django", indent=2)

formatted = format_text(config, "<div><p>hi</p></div>")

for finding in lint_text(config, '<img src="a.png">', filename="templates/home.html"):
    print(finding.line, finding.column, finding.code, finding.message)
```

## load_config

`load_config(folder=".", /, *, python_rules=True, **options)` читает конфигурацию, которая действует для файлов папки. Он ищет её вверх от этой папки, как командная строка ищет от текущего каталога, и не меняет текущий каталог.

Параметры называются так же, как параметры командной строки, только с подчёркиваниями, и работают так же: заданное значение важнее файла конфигурации, а `False`, пустая строка и, для большинства параметров, `0` считаются не заданными. Пути передаются как `pathlib.Path`.

Чтение конфигурации занимает некоторое время, поэтому храните результат, пока не изменятся файлы, из которых она прочитана. Его можно использовать для любого количества текстов.

С `python_rules=False` пользовательские правила с `python_module` не загружаются, поэтому код проекта, которому вы не доверяете, не запускается. Их имена находятся в `config.skipped_rules`.

## format_text

`format_text(config, text, /)` возвращает отформатированный текст. Текст, первая строка которого заканчивается на CRLF, возвращается с CRLF, любой другой — с LF. С `require_pragma` текст без прагмы возвращается без изменений.

## lint_text

`lint_text(config, text, /, *, filename="-")` возвращает список `Finding` в том порядке, в каком они встречаются в документе. С `filename` сопоставляется `per-file-ignores`. С `require_pragma` у текста без прагмы замечаний нет.

`Finding` — именованный кортеж со следующими полями:

::: content

- `code`: код правила, например `H013`.
- `message`: что сообщает правило.
- `match`: начало найденного текста, не более 20 символов.
- `line`, `column`: где начинается замечание. Строки считаются с 1, а столбцы — с 0.
- `end_line`, `end_column`: позиция сразу за его концом; она может оказаться на одной из следующих строк.
:::

Столбцы считаются в символах, а не в байтах или кодовых единицах UTF-16.

## is_excluded

`is_excluded(config, path, /)` сообщает, исключают ли файл `exclude`, `extend_exclude` или gitignore, так же как это делает командная строка. Сами `format_text` и `lint_text` этого не проверяют.

## Модули правил

`python_module` пользовательского правила импортируется один раз за процесс, из корня проекта, к которому относится конфигурация. Долго работающая программа, которая обслуживает несколько проектов, должна удалить из `sys.modules` всё, что было импортировано из проекта, а также корень проекта, который остаётся в конце `sys.path`, чтобы прочитать модули другого проекта.
